# Local summaries: deviations from the plan

1. **Task 1 (the `claude -p` gate) was skipped at the owner's request.** The owner ran the command in their own terminal; it printed nothing useful (calls ended in `Execution error`, with a settings warning from `~/.claude/settings.local.json` when run from the home folder). The owner chose to skip the check and continue. Real `claude -p` behaviour is therefore unverified; everything is tested against a fake runner. The usage-limit fixture is hand-written (a guess).
2. **`FakeLlm` moved to core in Task 2, not Task 3.** The moved `transcript.test.ts` uses `FakeLlm`, `text` and `tool`, so `packages/core/test/fake-llm.ts` (with those helpers) was created in Task 2. The server's `helpers.ts` re-exports them.
3. **The merge prompt line change ("digests below") landed in Task 3**, as the plan says, so Task 2 stays a pure move.
4. **`PageInputs.onReviewSkipped` added (Task 3).** The worker's existing test expects a "review skipped" log line when the review fails; `buildStatePage` swallows the failure as specified, so an optional callback lets the worker keep logging it. Not in the plan's interface.
5. **Existing tests changed in Task 4.** Four worker tests (`rebuilds the page without a deleted session…`, `keeps the digest and leaves the page for later…`, `keeps the page stale when a session is deleted while the page is being rebuilt`, `on a rebuild that does not fit…`) relied on the server rebuilding every `dirty` page. The plan stops that (spec decision 15), so they now queue the project with `queueServerPage` first, and the race test expects the stale save to be refused (`'error'`, then `'state'` after the retry wait). `digest-store.test` exact-shape expectations gained `version`, `digests_through`, `written_by` and `saved_seq`. The migration tests rewind through a new `unmigrate9` helper, and the migration 8 test asserts `SCHEMA_VERSION >= 8`.
6. **`saveDigest`'s `writtenBy` is optional** (defaults to the server, `null`), so the existing callers and tests did not need to change. `nextProjectNeedingState` is kept (only tests use it now); the worker uses `nextServerPage`.
7. **`savePageIfVersion` numbers a new page version 1**, and each save adds 1. The server's own page save now throws "the page was changed while it was being written" when the version moved, which the worker treats like any failed page update (retry with backoff).
8. **Legacy pending notes (Task 7).** The plan says the worker no longer handles notes. A note saved before this change still has a pending digest, so the worker keeps one small branch that writes it with `writeNoteDigest` (no model call). New notes never reach it. Its worker tests were rewritten (a note is `ok` at save time; searchable at once; the page is left to a computer's next sync).
9. **Task 7 test changes.** The MCP `search accepts source note` test now accepts two hits (the note's message and its digest, which is indexed at save time). The health fixture now has a project page, since a project with ok digests and no page counts as `pages-behind`. The `digests-off` test became a `summaries-waiting` test.
10. **`SessionSummary` gained `digest_written_by` and `digest_model`** (used by the dashboard's summary column, and so also present in `get_project`/`get_session` output).
11. **`summaries-waiting` text** says "Run hub resummarize" without backticks (the dashboard renders text escaped).
12. **`claude` runs from a fixed empty folder (Task 8).** In the owner's Task 1 attempt, `claude -p` run from the home folder printed a permission-rule warning from `~/.claude/settings.local.json` and ended in `Execution error`. So `spawnRunner` sets `cwd` to an empty folder of its own (`<tmp>/context-hub-summaries`), whatever folder a sync was started from. The runner's signature is unchanged. Whether that alone fixes the owner's error is unverified.
13. **Failure fixtures are hand-written guesses (Task 8).** `claude-ok`, `claude-refusal`, `claude-not-logged-in` and `claude-usage-limit` are written from the documented JSON shape (the usage-limit reset time as epoch seconds after a pipe is the old format), not captured. Each says so in a `_note` field. Recognising a real limit response is unverified.
14. **Tests briefly reached the real `claude` (Task 9) — please note.** When `runSync` started building a `ClaudeCodeLlm` by default, the existing CLI, auto-sync and server e2e tests (which pass no fake `llm`) found the owner's real `claude.exe` through `findClaude()`. Three test runs (the full suite, then the collector tests, then one CLI test) therefore started real `claude -p` calls with tiny prompts from the test fixtures. They ended in errors within about a second and nothing was used from them, but they may have counted against the plan. This was fixed in the same task: `vitest.config.ts` and `apps/collector/test/setup.ts` mock `findClaude` to return null for every test, and the CLI, auto and e2e tests pass a `FakeLlm`. `Io.llm` was added to the CLI for that.
15. **Task 9 shape changes.** `getStatus` is now called once after uploads of documents and re-cleaned sessions (a `GET /api/status` appears in the request list of a sync; the CLI test for `hub sync` lists it). Waiting reasons are the user-facing text ("Claude usage limit reached (resets 14:00)", "cap of 20 reached. Run hub sync --all to catch up", "Claude Code is not installed", "summary failed: <message>"). An empty session costs no cap slot (no model call). `catchUpOwed` returns `{ written, waiting, failure }` instead of calling an `onDone` callback.
16. **Task 10: sync integration written before its tests.** `updatePages` was written test-first (its 11 tests failed first). The `runSync` hook that calls it was written before the matching `sync.test.ts` tests, so those tests were never seen failing for the missing hook; instead, disabling the hook was shown to fail 3 of them.
17. **Ruling (Task 10): a re-cleaned project's page waits for its summaries.** A re-clean marks the project's page dirty and removes its sessions' digests. Rebuilding the page at once would build it without those sessions, and again later. So `runSync` leaves the page of any project that uploaded a `summary_to_follow` session in this run, or still has owed summaries after catch-up, and reports it in `pages.left`; the page is rebuilt on the sync that has written the digests. Cost if wrong: the old page, which may hold the data cleaning removed, stays on the hub for one more sync (the sessions' own text is replaced at once).
18. **`updatePages` takes no `writtenBy`.** The hub records the writer from the token label, so the option had nothing to do.
19. **Task 11: CLI tests were run after the CLI code was written.** The auto-sync lock tests were seen failing first (missing exports). For the CLI (`--all`, waiting/pages lines, `hub status`, `hub summaries`, the doctor rows) the code was written before the new tests were first run, so those tests were not seen failing; they exercise behaviour that did not exist before.
20. **Task 11 shape changes.** `Io.runClaude` now takes the `claude` arguments (the existing doctor tests' stand-ins were updated to answer `auth status --json`). `hub status` prints the server's JSON first and then plain lines about waiting sessions, pages needed and summaries owed. The doctor's `claude auth status --json` runs through `findClaude()` and `cleanEnv()`; when only a `.cmd` shim exists on Windows it says so (`claudeOnlyAsCmd`). The auto-sync log line (and its error line) always carries `N summarized, M waiting`. An extra doctor row, "Waiting summaries", shows what the last sync left waiting. Not run against a real `claude`: the doctor's real runner is unverified.
